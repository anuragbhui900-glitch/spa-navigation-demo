Week 5 – SPA Simulation

Project Overview

This project demonstrates a Single Page Application (SPA) developed using HTML5, CSS3, and JavaScript. It simulates multiple pages within a single HTML document by dynamically updating content without reloading the entire website.

The project was created as part of the YuvaIntern Frontend Web Developer Internship.

Objectives

- Understand the basic concepts of Single Page Applications.
- Implement dynamic content rendering using JavaScript.
- Create navigation using URL hash changes.
- Support browser Back and Forward navigation.
- Design a responsive and accessible user interface.
- Implement client-side contact form validation.

Technologies Used

- HTML5: Semantic webpage structure.
- CSS3: Styling, responsive layouts, and media queries.
- JavaScript: DOM manipulation, event handling, dynamic routing, and form validation.

Features

1. Single Page Application Simulation: Changes page content without reloading the entire document.
2. Dynamic Navigation: Includes Home, Projects, About, and Contact views.
3. URL Hash Routing: Updates the URL using hash-based navigation.
4. Browser History: Supports Back and Forward navigation through the browser.
5. Responsive Design: Adapts to desktop, tablet, and mobile screens.
6. Contact Form Validation: Checks required fields and validates the email format.
7. Accessibility: Includes semantic HTML, keyboard focus indicators, and a skip-to-content link.
8. 404 View: Displays a message when an unknown route is requested.

How to Run the Project

1. Download or clone this repository.
2. Open the project folder in Visual Studio Code.
3. Make sure "index.html", "style.css", and "script.js" are in the same folder.
4. Open "index.html" in a web browser, or use the Live Server extension in VS Code.
5. Click the navigation links and test the website features.

Learning Outcomes

Through this project, I practised HTML structure, CSS responsive design, JavaScript DOM manipulation, event handling, hash-based routing, browser history navigation, and client-side form validation.

Limitations

This is a frontend demonstration. The contact form does not send messages to a server, and the project does not use a backend or database.
